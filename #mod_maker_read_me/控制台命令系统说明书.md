# 控制台命令系统说明书（Console Command System）

> 项目：HelloNyxel ／ Godot 4.7 ／ GDScript
> 统一命令解释器：`autoload/console_command.gd`（`class_name ConsoleCommand extends RefCounted`）
> 属性序列化：`ui/block_property.gd`（`BlockProperty.prop_to_command`）

---

## 1. 这是什么

一套**统一命令语言（DSL）**，用于以「英文、程序员习惯」的写法来操控积木世界：

- 创建 / 删除积木
- 读写积木属性（宽高、位置、颜色、标签、碰撞层、文本框、攻击框……）
- 读写全局变量、JSON 文件变量
- 在条件中按属性筛选积木

同一套语言被三处共用，写法 100% 一致：

| 入口 | 触发方式 |
| --- | --- |
| **控制台面板** | 调试面板里点「控制台」，在输入框敲命令并回车 |
| **事件链按钮效果** | 事件链编辑器里按钮的 `effect` 字段，以 `/` 开头即执行 |
| **时间轴触发** | 时间轴 `{}` 触发内容，以 `/` 开头即执行 |

设计原则：纯递归下降解析，**无 `eval`**；任何语法/语义错误都转为友好报错，绝不崩溃。

---

## 2. 命令总览

所有命令以 `/` 开头，命令名、参数均为英文。

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `/create_block` | 创建积木（可选 `block_type` 先克隆类型） | `/create_block { string_id="x", width=120, tags={gravity} }` |
| `/remove_block` | 删除满足条件的积木 | `/remove_block if ( this:tags has "gravity" )` |
| `/set_var` | 设置变量（覆盖 / 运算赋值） | `/set_var 12:width = 80` |
| `/add_var` | 新增变量 / 集合元素 | `/add_var 12:tags = "flag"` |
| `/remove_var` | 移除变量 / 集合元素 | `/remove_var 12:tags = "flag"` |
| `/help` | 打印帮助（可带具体命令名） | `/help create_block` |
| `/clear` | 清空控制台输出（仅 UI 生效） | `/clear` |
| `/add_timeline` | 把一条命令**预定**到时间轴（到点由时间轴触发） | `/add_timeline { after="10m", effect="/set_var a = 1" }` |
| `/add_tag` | 给某个**已注册状态**加一条标签（条件 `has_tag` 判的就是它） | `/add_tag 剧情状态 得到钥匙` |
| `/remove_tag` | 移除一条标签（本来就没有 = 成功） | `/remove_tag 剧情状态 得到钥匙` |
| `/clear_tags` | 清空某状态某标签字段的全部标签 | `/clear_tags 荧惑日常状态 mood` |

多条命令可用 `;` 或换行分隔，写在同一段文本里一次性执行；引号内、`()`、`{}` 内的 `;` 不分割。

> **标识符里的中文**：状态名 / 标签名 / 事件名可以直接裸写（`/add_tag 剧情状态 得到钥匙`）。
> 只有**含空格**的名称才必须加引号（`/load_level "测试 1"`）。

## 3. `/create_block` —— 创建积木

```
/create_block { <属性> = <值>, ... }
```

- 可选 `block_type="类型名"`：**先克隆已登记的类型**，其后的键再覆盖它；不写则创建空白积木。
- 其余键直接作为属性应用（`BlockProperty.apply_to_block`）。
- 重复键**以最后为准**。
- 无 `position` 时落在桌面中心附近。

### 支持的属性键

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `string_id` | 字符串 | 积木的字符串 ID（唯一），可被变量引用 `A:B:C` 的 A 段命中 |
| `id` | 整数 | 强制重指定数字 ID（须 >0 且未被占用） |
| `position` | `Vector2` | 桌面坐标 `(x, y)` |
| `width` / `height` | 数字 | 尺寸（1..4096） |
| `display_layer` | 整数 | 渲染层级 |
| `collision_layer` | 集合 | 碰撞图层名集合，如 `{default, dragging}` |
| `border_color` / `fill_color` | 字符串 | 十六进制颜色 `#RRGGBB` / `#RRGGBBAA` |
| `border_width` | 数字 | 边框宽度 |
| `tags` | 集合 | 标签集合，如 `{gravity, draggable, collision}` |
| `fill_path` | 字符串 | 填充图片/动图路径（空 = 清除填充） |
| `fill_mode` / `fill_anim` | 整数 | 填充模式 / 动画类型 |
| `rotation_deg` | 数字 | 旋转角度（度） |
| `facing` | 整数 | 朝向：`1`=右，`-1`=左 |
| `base_attack` | 数字 | 基础攻击力 |
| `text_boxes` | 集合（字典） | 文本框列表，元素为 `{ name=..., width=..., text_def=..., text_defs={...} }` |
| `attack_boxes` | 集合（字典） | 攻击判定框列表，元素为 `{ name=..., width=..., attack_power=... }` |
| `parent_id` | 整数 | 父级积木 ID（>0；成环保护由 Block 侧兜底） |
| `child_ids` | 集合 | 子级积木 ID 列表，如 `{2, 3}` |

> 文本框 / 攻击框用**嵌套字典**表示，可任意嵌套（见 §5 字面量）。
>
> 文本框多语言：`text_defs` 是「语言代码 → `(修饰)[内容]` 定义」的字典（如 `{ en="(C)[Recycle Bin]", ja="(C)[ゴミ箱]" }`），
> 语言代码见 `TranslationManager.LANG_CODES`。玩家语言命中该键就用它，没配的语言（含缺失字段）
> 一律回落到 `text_def`；此外正文还会按 `data/translations.tsv` 再兜底翻一次，
> 所以**只写 `text_def` 的存量数据也会跟随语言**，无需迁移存档。

示例：

```
/create_block {
  string_id="hero",
  block_type="玩家",
  position=(320, 240),
  width=128, height=96,
  tags={show, border, collision, gravity},
  collision_layer={default},
  border_color="#FF8800",
  fill_color="#224488",
  facing=-1,
  rotation_deg=15,
  text_boxes={ { name="bubble", width=200, height=48, text_def="你好 {name}" } }
}
```

## 4. `/remove_block` —— 删除积木

两种判定方式，可单独使用，也可叠加：

```
# 方式一：谓词并列（多个 key=value 之间是 AND）
/remove_block { string_id="hero" }

# 方式二：条件表达式（this / self 指代“当前被判定积木”）
/remove_block if ( this:tags has "gravity" and this:width > 100 )

# 叠加：谓词 AND 条件
/remove_block { string_id="tmp" } if ( this:width > 50 )
```

- **必须**提供 `{preds}` 或 `if (cond)` 之一，二者皆空会拒绝执行（避免误删全部积木）。
- 遍历注册表逐块判定：`preds` 全部匹配 **且** `cond` 为真才删除。

## 5. 变量与值

### 5.1 变量引用 `<ref>` = `A[:B[:C...]]`

第一段 `A` 的解析优先级：

1. **纯数字** → 该数字 ID 的积木（`BlockManager`）；
2. **已存在的 `string_id`** → 对应积木；
3. **以 `.json` 结尾 / `temp` 目录下的文件** → JSON 文件（返回 Dictionary / Array）；
4. 否则 → **全局变量**（`GlobalVars`）。

后续段 `B` / `C` 在上一层结果里导航：

- 积木：`B` = 属性名（`width` / `height` / `position` / `string_id` / `tags` / …），`C` = 集合元素下标；
- 文件 / Dictionary：`B` = 键，`C` = 嵌套键；
- 集合读取用下标；写入集合元素用 `/add_var` / `/remove_var`。

在 `if (cond)` 里，`this` / `self` 专指「当前被判定积木」。

### 5.2 字面量（值）

| 字面量 | 写法 | 说明 |
| --- | --- | --- |
| 数字 | `12` / `3.5` / `-8` | 支持负数（一元负号） |
| 字符串 | `"abc"` 或 `'abc'` | 支持 `\"` `\n` `\t` 转义 |
| 布尔 | `true` / `false` | 关键字 |
| 空 | `null` | 关键字 |
| 向量 | `(100, 200)` | `Vector2`，分量可为负 |
| 集合 | `{a, b, c}` | 数组 / 集合；元素为字面量，裸词按字符串处理 |
| 字典 | `{k = v, k2 = v2}` | 键为名称，值递归解析；**可任意嵌套**（文本框/攻击框用此表示） |

> 集合与字典的区别：集合元素是「值」，字典元素是「`键 = 值`」。解析器通过前瞻自动区分二者。

### 5.3 运算符（条件 `if` 内）

- 逻辑：`and` `or` `not`
- 比较：`==` `!=` `<` `>` `<=` `>=`
- 算术：`+` `-` `*` `/`
- 成员判定：`has`（如 `this:tags has "gravity"`）
- 括号：`()` 可任意嵌套

**优先级**：`not` > 比较 > `and` > `or`；算术高于比较；`()` 最高。

## 6. 变量读写命令

### `/set_var <ref> = <value>`
覆盖赋值，运算符 `op ∈ = += -= *= /=`。

```
/set_var 12:width = 80
/set_var this:position += (50, 0)
/set_var player.json:age = 18
/set_var score *= 2
```

### `/add_var <ref> = <value>`
Dictionary 加键；Array / Packed*Array 追加元素。

```
/add_var 12:tags = "flag"          # 给积木加标签
/add_var player.json:inventory = {sword, shield}
```

### `/remove_var <ref> [= <value>]`
- **带 `=`**：从集合中删除某个元素；
- **不带 `=`**：删除键 / 清空（全局变量置 `null`）。

```
/remove_var 12:tags = "flag"       # 删除某标签
/remove_var player.json:age        # 删除 JSON 里的键
/remove_var temp_score             # 全局变量置 null
```

## 7. 三处统一接入

以下三处，只要内容以 `/` 开头，就交给 `ConsoleCommand.exec` 执行——**写法完全相同**：

1. **控制台面板**（调试面板「控制台」开关，CanvasLayer 承载）
   输入框回车或点「执行」→ 执行；支持 `Tab` 补全、↑/↓ 历史、前缀候选。

2. **事件链按钮效果**（`autoload/event_chain_runner.gd` 的 `_run_effect`）
   按钮 `effect` 字段内容以 `/` 开头即执行。

3. **时间轴触发**（`autoload/timeline_manager.gd` 的 `_fire`）
   触发内容以 `/` 开头即执行；保留 `event:` 事件链快捷方式与 `timeline_fired` 信号兜底。

```
# 在事件链按钮 / 时间轴里与控制台里完全一致的写法：
/create_block { string_id="boom", tags={gravity}, position=(400,300), width=64 }
/remove_block if ( this:tags has "boom" )
/set_var score += 1
```

## 8. 属性面板「复制为命令」

在积木属性面板（`PropertyEditorPanel`）点 **「复制为命令」** 按钮：

- 读取当前面板收集到的全部属性（与「确定」应用的是同一份数据）；
- 由 `BlockProperty.prop_to_command(prop, block)` 序列化为一条 `/create_block { ... }` 文本：
  - 含当前积木的 `global_position`（单块编辑时）；
  - 文本框 / 攻击框会被展开为嵌套字典，完整保留（名称、尺寸、文本、颜色……）；
  - 自动跳过「空/零」哨兵值（`id=0`、`string_id=""`、`fill_path=""`、空子级/文本框/攻击框），避免回放出无效赋值；
- 文本复制到系统剪贴板，并打印到控制台日志。

之后在**控制台**粘贴即可原样重放创建一块相同积木——非常适合批量布置、模板复用、或把调好的积木分享给事件链/时间轴。

```
# 「复制为命令」可能生成的文本示例：
/create_block { position = (320,240), width = 128, height = 96, display_layer = 1,
  collision_layer = { "default" }, border_color = "#FF8800", fill_color = "#224488",
  tags = { "show", "border", "collision", "gravity" }, rotation_deg = 15, facing = -1,
  base_attack = 2.5,
  text_boxes = { { name = "bubble", width = 200, height = 48, text_def = "你好 {name}", hide_when_empty = true } } }
```

## 9. 常用配方（Cheat Sheet）

```
# 一键造一块会掉的重块
/create_block { string_id="rock", tags={gravity, collision}, position=(200,100), width=48, height=48 }

# 把所有「重力块」宽度翻倍
/set_var this:width *= 2   # （配合 remove_block 的 if 遍历思维；实际遍历用下方）

# 删除所有宽度在 100~300 之间的积木
/remove_block if ( this:width > 100 and this:width <= 300 )

# 给所有块加一个标签
# （遍历需借助脚本；控制台内置只按谓词/条件删，可按需扩展）

# 全局计分
/set_var score = 0
/add_var score += 1

# 读某块属性到全局变量
/set_var w = 12:width

# 清空控制台
/clear
```

## 10. 排错

| 现象 | 原因 / 解决 |
| --- | --- |
| `未知命令：/xxx` | 命令名拼错，输入 `/help` 查看可用命令 |
| `未知输入...命令须以 / 开头` | 忘了开头的 `/` |
| `remove_block 需要 {predicates} 或 if (cond)` | 删块必须给谓词或条件，不能空删 |
| `bag 键应为名称` | `{}` 内键必须是英文标识符（`key = value`） |
| `无法解析的值：...` | 值不是合法字面量；负数请用 `-1`（一元负号已支持），不要用 `--1` |
| `dict 需要 key = value` | 字典元素必须写成 `键 = 值`，不能只写值 |
| 变量引用读不到 | 检查 A 段：数字→ID、string_id→积木、`.json`→文件、否则全局变量 |
| `this/self` 在条件外无效 | `this`/`self` 仅在 `remove_block if (...)` 内指代当前积木 |

## 12. `/add_timeline` —— 添加到时间轴

**语义：提前生效。** 时间轴本质是「定时（段）执行命令」的计划表，所以这条命令**立刻**把一条
待执行记录写进 `%Documents%\HelloNyxel\Temp\timeline.txt` 并落盘，**不进入任何「待确认」状态**；
到点后由 `TimelineManager` 自己检查并触发。控制台只负责「预定」。

```
/add_timeline { after="10m", effect="/set_var a = 1", event="链/事件名", tag="笔记", ignore=1 }
```

### 参数

| 键 | 必填 | 说明 |
| --- | --- | --- |
| `after` | 与 `time` 二选一 | **预计时间（相对）**：`"90s"` / `"10m"` / `"2h"` / `"1d"`，可拼接（`"1h30m"`）；纯数字 = 秒（`"120"`，不加引号的 `120` 也可以）。也接受中文单位 秒/分/分钟/小时/天/日 |
| `time` | 与 `after` 二选一 | **预计时间（绝对）**：`"2026.10.11.20:00:00"`（本地时间）。两个都写会**报错**（避免静默丢掉其中一个） |
| `effect` | 与 `event` 至少一个 | **时间轴效果**：要执行的命令（以 `/` 开头） |
| `event` | 与 `effect` 至少一个 | **触发事件**：`"事件链/事件名"`（必须带链名，计划文件用 `event:` 前缀分派） |
| `tag` | 否 | 事件标签（仅供归类 / 排查） |
| `ignore` | 否 | `1` = 忽略「同时触发上限」 |
| `delay` | 否 | 读档后延迟多少秒才允许触发 |
| `max_skip` | 否 | 最多被忽略多少次；`skip >= max_skip` 时下次无条件触发 |

`effect` 与 `event` **可以同时给** → 在同一预计时刻写**两条**记录，靠写入顺序保证
**先执行效果、再触发事件**（同刻排序用内部自增序号，顺序稳定，不受排序算法是否稳定影响）。

### 为什么不写「绝对时间」也能预定

`after` 会当场换算成绝对时刻再写盘。因为时间轴有「同时触发上限 / 读档延迟」等机制，
**实际触发可能晚于该时刻**，所以界面上这个词统一叫**「预计时间」**。

```
# 10 分钟后给全局变量加 1
/add_timeline { after="10m", effect="/set_var score += 1" }

# 半小时后播放一个事件
/add_timeline { after="30m", event="初次见面/初次见面" }

# 今晚 20:00 同时「加个分」并「播放事件」（同刻两条，先效果后事件）
/add_timeline { time="2026.10.11.20:00:00", effect="/set_var score += 10", event="日常/送礼" }
```

### 错误分支（都会明确报错，不静默）

| 输入 | 结果 |
| --- | --- |
| 既无 `after` 也无 `time` | 报「缺少预计时间」 |
| `after` 与 `time` 同时给 | 报「只能给一个」 |
| 既无 `effect` 也无 `event` | 报「缺少内容」 |
| `event` 不带 `链/` | 报「须写成事件链/事件名」 |
| `after="abc"` | 报「after 格式不正确」 |
| 出现未知属性键 | 报「不认识的属性」并列出可用键 |

> 可视化入口：「效果编辑」页的命令下拉选「添加到时间轴」，字段为
> **预计时间 / 时间轴效果 / 触发事件 / 其他属性**（绝对时刻会自动补全到秒 `HH:MM → HH:MM:SS`）。

## 13. `/add_tag` · `/remove_tag` · `/clear_tags` —— 状态标签

**为什么需要它**：条件编辑器里能写 `has_tag("剧情状态","得到钥匙")`，可「效果」侧当年只有
「变量」——而 `/set_var` 的右侧**不支持数组字面量**，所以「给状态加个标签」这件事在效果侧
根本表达不出来。这三条命令把缺口补上（并与条件侧的 `has_tag` 严格对称）。

### 13.1 标签是什么

> 标签 = 某个**已注册状态**（`StateRegistry`）里某个「字符串数组」字段的一个元素。
> 判定口径与 `EventExpr.has_tag` **完全一致**：遍历该状态 JSON 的**所有**数组字段找这个字符串。

状态 JSON 是单一真源：条件求值时**每次现读文件** → 写完标签立刻生效，不需要任何广播。

```
/add_tag 剧情状态 得到钥匙                    # → story_state.json: {"tags": ["得到钥匙"]}
/add_tag "剧情状态" "得到钥匙" "tags"          # 含空格才需要引号；字段也可显式给
/add_tag { state="剧情状态", field="tags", tag="得到钥匙" }   # bag 写法
/remove_tag 剧情状态 得到钥匙
/clear_tags 荧惑日常状态 mood
```

### 13.2 `field` 省略时的自动规则（绝不猜）

| 该状态的字段候选 | 结果 |
| --- | --- |
| 只有 1 个 | 自动用它（如「剧情状态」里已有 `flags` → 写进 `flags`） |
| 一个都没有 | 新建 `tags` 字段 |
| 有 2 个及以上 | **报错**并要求写明 `field`（如「荧惑日常状态」有 `mood` / `desire`） |

### 13.3 各状态的可写字段

| 状态 | 文件 | 可写字段 | 说明 |
| --- | --- | --- | --- |
| 荧惑日常状态 | `nyxel_daily_state.json` | `mood` / `desire` | 它自己的两个「标签集」→ 走 `NyxelDailyState` 的 API（归一化 / 条数上限 / 变更广播） |
| 荧惑剧情状态 | `nyxel_story_state.json` | 任意字符串数组字段，无则新建 `tags` | 自由字典 |
| 世界状态 | `world_state.json` | 同上 | 自由字典 |
| 剧情状态 | `story_state.json` | 同上 | 自由字典 |
| 玩家画像 | `player_profile.json` | `tags`（新建） | 顶层没有字符串数组字段 |
| 设备清单 | `devices.json` | `tags`（新建） | `devices` 是对象数组，不算标签字段 |
| 背包清单 | `inventory.json` | `tags`（新建） | `items` 是对象数组，不算标签字段 |

> 「玩家画像 / 设备清单 / 背包清单」这三份由各自系统**按内存模型整份重建**文件，所以
> `StateRegistry` 只在那里新建 `tags` 一个键，并且写盘后会让对应系统**重新读盘**；
> 那三个系统的读盘代码也已改成**保留未知顶层键**，因此它们再保存时不会再抹掉标签。

### 13.4 语义与错误分支

| 输入 | 结果 |
| --- | --- |
| 标签已存在（`/add_tag`） | 成功，`changed=false`，提示「已存在」 |
| 标签本来就没有（`/remove_tag`） | 成功，`changed=false`（不报错） |
| 状态未注册 | 报「未注册的状态」并列出可用状态 |
| 字段名已存在但不是数组 | 报「不是数组」→ **拒绝覆盖** |
| 字段是「对象数组」（如 `history` / `items`） | 报「不是字符串数组」→ 拒绝写入 |
| 标签为空 | 报「标签不能为空」 |
| 多候选字段且未写 `field` | 报「多个标签字段」并列出候选 |

```
# 5.1 场景：走到某处 → 给剧情状态打标记
/add_tag 剧情状态 已见过荧惑

# 5.2 场景：喝下咖啡 → 荧惑的欲望集里加一条
/add_tag 荧惑日常状态 想睡个午觉 desire

# 5.3 场景：重置某状态的所有标记
/clear_tags 剧情状态
```

> 可视化入口：「效果编辑」页的命令下拉选**添加状态标签 / 移除状态标签 / 清空状态标签**，
> 字段为 **状态 / 标签字段 / 标签**（状态下拉 = 全部已注册状态；标签字段下拉 = 该状态现有的
> 字符串数组字段，只有一个候选时自动选中）。
> 反过来，**条件编辑器**的「状态标签」谓词里，「标签名」也是同一个来源的**下拉**（+ 可手填新标签）。
